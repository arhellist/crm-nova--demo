## 1. Контекст и проблема

После «Принять» пользователь ожидает, что смена статуса больше недоступна. RPC уже
отклоняет исходящие из `accepted` (`P0422`), но UI после успеха мог кратко показывать
кнопки до refetch и не сообщал о фиксации явно.

## 2. Предлагаемое решение

В карточке и строке списка при `accepted` не предлагать переходов; сразу после успешного
«Принять» опираться на статус из ответа RPC; показать подпись «Статус зафиксирован».
Инвалидировать `my-tasks` вместе с карточкой.

## 3. Обоснование и цели (Business Goals)

Терминальный статус цикла hh / domain-rules §1: из `accepted` переходов нет.

## 4. Затрагиваемые домены и контракты

- Домен `tasks`: StatusPanel, TaskRow; матрица `transitions.ts` уже `accepted: []`.

## 5. Риски и обратная совместимость (Backwards Compatibility)

`compatible` — только UX; RPC/RLS без изменений.

## 6. Что не делаем (Non-goals)

Не запрещаем правку title/description менеджером; не вводим новый статус.

## 7. Альтернативы

Автоархив при принятии — отвергнуто: архив отдельная операция.

## 8. Трассировка на требования

domain-rules §1; DEC-058.
