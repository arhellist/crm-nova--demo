## 1. Контекст и проблема

На локальном стенде (`http://127.0.0.1:4173`) после входа навигация, вкладки статусов, поля и кнопки визуально слипаются: нет gap, padding и сетки. Наблюдаемо: «Объекты» и «Мои задачи» читаются как одна строка, на вкладках «Все0» без пробела между подписью и счётчиком. Причина: production-сборка SPA кладёт в CSS сырые директивы `@tailwind` (~1 КБ), утилиты Tailwind не генерируются — нет `postcss.config`.

## 2. Предлагаемое решение

Подключить PostCSS с `tailwindcss` и `autoprefixer` к Vite-сборке фронтенда, импортировать локальные шрифты Inter / JetBrains Mono (design-notes, без CDN), убедиться что `dist/web` CSS содержит утилиты (`flex`, `gap`, `px-`, `rounded-sm`). Точечно поправить контролы только если после пайплайна останутся дефекты плотности — без смены палитры.

## 3. Обоснование и цели (Business Goals)

Пользователь не может уверенно работать с CRM: иерархия и зоны клика нечитаемы. Закрывает NFR доступности/UX из design-notes (сетка 8 px, контролы с отступами) и делает staging-сборку визуально равной задуманному UI D04–D12.

## 4. Затрагиваемые домены и контракты

- Домен `platform`: пайплайн стилей SPA (`postcss.config.cjs`, `src/styles/tokens.css`, `src/main.tsx`), артефакт `dist/web`.

## 5. Риски и обратная совместимость (Backwards Compatibility)

`compatible` — поведение API/RLS/маршрутов не меняется; меняется только CSS-артефакт сборки. Риск регрессии: увеличится размер CSS-бандла (ожидаемо) — в пределах `chunkSizeWarningLimit`.

## 6. Что не делаем (Non-goals)

- Не меняем палитру, радиусы и токены из `design-notes.md`.
- Не вводим светлую тему, CDN-шрифты, эмодзи-иконки, MUI/AntD.
- Не расширяем продуктовый объём (§2.2).
- Не переписываем layout экранов «с нуля», если после включения Tailwind плотность соответствует design-notes.

## 7. Альтернативы

- Инлайн-стили / CSS Modules на каждый экран — дублирует токены и ломает единый Tailwind-контракт.
- `cdn.tailwindcss.com` в runtime — запрещено CSP и INV-010.
