# Протокол проверки README на чистом клоне (`@acceptance A14.3`)

Цель: новый человек без вопросов автору поднимает контур за ≤15 минут (NFR18) и понимает,
где смотреть решения и риски (`docs/decisions.md`). Проверка выполняется на копии без
`node_modules`, `.git` и `dist`, чтобы не использовать уже собранные артефакты.

## 1. Шаги протокола

| № | Шаг | Команда | Ожидание |
|---|-----|---------|----------|
| 1 | Копия проекта без артефактов | `tar --exclude=node_modules --exclude=.git --exclude=dist -cf - . \| tar -xf -` | в копии нет `node_modules` |
| 2 | Установка зависимостей | `npm ci` | код 0, lock-файл не меняется |
| 3 | Линт | `npm run lint` | код 0, 0 предупреждений |
| 4 | Типы src + e2e | `npm run typecheck` | код 0, оба проекта strict |
| 5 | Тесты | `npm run test` | код 0, все файлы зелёные |
| 6 | Supabase | `npx supabase start && npx supabase db reset` | контур поднят, seed идемпотентен |
| 7 | Приложение | `npm run dev` | `:5173` открывается, вход с MFA работает |
| 8 | Решения и риски | открыть `docs/decisions.md` | риски и принятые advisories объяснены без вопросов |

Проверки фиксируются вызовами `check(шаг, код, ожидание)`; шаг считается пройденным только
при совпадении кода.

## 3. Критерии успеха

- Все шаги README выполнимы дословно, без обращения к автору.
- Суммарное время до рабочего экрана — не больше 15 минут.
- `docs/decisions.md` объясняет остаточные риски и принятые предупреждения аудита.
- Секреты не требуются в репозитории: только `.env.local` из `.env.example`.

## 4. Повторение

Протокол повторяется перед каждым релизом и после изменения зависимостей, миграций или
переменных окружения. Результат вносится таблицей §2; расхождение с ожиданием — дефект
README, а не «особенность машины».
