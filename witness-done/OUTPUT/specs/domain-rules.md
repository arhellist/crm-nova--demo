# Доменные правила — NOVA CRM

> Сгенерировано Witness Done v1.31.0. Числа и формулировки, которые D-промпты не должны изобретать.
> Источник: ТЗ §5.3, §5.4, §13.1; `specs/data-model.md`.

## 1. Машина состояний задачи

| Из | В | Кто | Условие |
|----|----|-----|---------|
| — | `new` | постановщик | создание задачи; иной стартовый статус невозможен |
| `new` | `in_progress` | назначенный исполнитель | `assignee_id = auth.uid()` |
| `in_progress` | `on_review` | назначенный исполнитель | `assignee_id = auth.uid()` |
| `on_review` | `accepted` | постановщик | роль `manager` |
| `on_review` | `rework` | постановщик | роль `manager` + непустой комментарий |
| `rework` | `in_progress` | назначенный исполнитель | `assignee_id = auth.uid()` |

Все прочие пары (15 из 25, включая переход в тот же статус) запрещены: `P0422`, статус не меняется,
история не пополняется. Терминального «удаления» нет: принятая задача может быть архивирована
постановщиком.

## 2. Создание и правка задачи

- Обязательные поля: `title` (1–200), `assignee_id`, `object_id`. `description` — до 5000, может быть пустым.
- `author_id` = текущий пользователь, роль `manager`; назначать можно только пользователя с ролью `executor`.
- Объект задачи не архивирован.
- Смена исполнителя разрешена только в `new` и `rework`; в `in_progress`/`on_review` — `P0422`.
- `status` в `INSERT`/`UPDATE` от клиента не принимается: колонка не входит в грант, триггер отклоняет.

## 3. Комментарии

- Обязателен при `on_review → rework`, максимум 2000 символов; пустая строка и строка из пробелов
  не считаются комментарием.
- В остальных переходах необязателен; если передан — сохраняется в истории.
- Комментарий не редактируется и не удаляется.

## 4. Архивирование

- Только постановщик, идемпотентно (`deleted_at is null` → выставить `now()`).
- Объект и задача: после архивирования не видны в списках и карточках ни одной роли.
- Задачи архивированного объекта скрываются каскадно, но их строки не меняются.
- История сохраняется полностью; физическое удаление невозможно.

## 5. Доступность и видимость

- Исполнитель видит только задачи с `assignee_id = auth.uid()` и неархивированные.
- Исполнитель видит объект, если в нём есть хотя бы одна его неархивированная задача (в любом статусе,
  включая принятые).
- «Не существует» и «нет доступа» не различаются: пустой массив на чтение, 404 на экран.
- Исполнитель не может править поля задачи (нет грантов), только двигать статус своих задач.

## 6. Ошибки (стабильные коды)

| SQLSTATE | Когда | Текст для пользователя |
|----------|-------|------------------------|
| `P0400` | ошибка валидации, объект/задача не найдены, пустой обязательный комментарий на входе | «Проверьте заполнение полей» |
| `P0403` | нет прав: чужая задача, попытка прямой смены статуса, запись в историю, архивирование исполнителем | «Нет доступа» |
| `P0422` | недопустимый переход, смена исполнителя в запрещённом статусе, отсутствие комментария при возврате | «Недопустимое действие для текущего статуса» |
| `E_INTERNAL` | ошибка backend | «Не удалось получить данные, попробуйте позже» |
| `E_REPLICA_LAG` | лаг репликации выше порога | «Данные отчёта временно недоступны» |

Клиент маппит коды в человеческий текст; SQL-детали наружу не отдаются.

## 7. Отчётность (вторичные данные)

- `lag_seconds` — разница `pg_current_wal_lsn()` и `confirmed_flush_lsn` в секундах, округление вниз.
- Порог деградации: `lag_seconds > 30` → `/health/replication` возвращает `503`, отчёты — `503 E_REPLICA_LAG`.
- Кэш ответа в процессе API — не более 30 секунд; ключ включает набор параметров отчёта.
- В ответах нет email, `description`, комментариев; только агрегаты и `full_name`.

## 8. Время и локали

- Хранение — `timestamptz` в UTC. Отображение — `dd.MM.yyyy HH:mm`, часовой пояс Europe/Moscow.
- Сутки для отчётов — календарные сутки Europe/Moscow.
- Язык интерфейса — русский, без i18n-фреймворка.

## 9. Лимиты

- `title` объекта — 200, `address` — 300, `title` задачи — 200, `description` — 5000.
- Комментарий перехода — 2000. `full_name` — 120.
- `limit` списков — по умолчанию 50, максимум 100. Параметры отчётов валидируются Zod.
- Rate limit API: 60 запросов в минуту на токен; при превышении — `429`.
