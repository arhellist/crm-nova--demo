# Политика зависимостей

> Сгенерировано Witness Done v1.31.0. Цель: обновления предсказуемы, а новая зависимость — решение,
> а не побочный эффект.

## 1. Правила добавления

1. Новая runtime-зависимость добавляется только в рамках D-промпта и только если её нет в текущем
   стеке. Обоснование — в описании изменения (одна строка: какую задачу решает).
2. Запрещено: UI-киты (MUI/AntD/Bootstrap), state-менеджеры (Redux/MobX), CSS-in-JS, тяжёлые
   date-библиотеки (Moment), любые пакеты для криптографии и JWT-верификации на клиенте.
3. Зависимость без поддержки (последний релиз > 18 месяцев) и без альтернативы — повод для
   `sp decide`.
4. `postinstall`-скрипты сторонних пакетов — ревью перед установкой.

## 2. Фиксация версий

- `package-lock.json` коммитится; CI использует `npm ci`, не `npm install`.
- Версии в `package.json` — точные или `~`: мажорные обновления только отдельным PR.
- Node.js 20 LTS фиксируется в `engines` и в CI.

## 3. Обновления

- Dependabot: patch/minor — еженедельно, major — вручную.
- Автомерж разрешён только для patch-обновлений dev-зависимостей, если `lint/test/typecheck` зелёные.
- Обновление, требующее миграции данных или изменения контракта, идёт через `sp intake --kind change`.

## 4. Аудит и уязвимости

- `npm audit --audit-level=high` обязателен в CI; critical/high — блокер merge.
- Уязвимость без исправления: оценка эксплуатируемости, `sp decide` с решением (митигация/перенос),
  запись в `improvement-backlog` не создаётся — решение фиксируется в журнале.
- Секреты в зависимостях не сканируются отдельно: работает `gitleaks` по репозиторию.
