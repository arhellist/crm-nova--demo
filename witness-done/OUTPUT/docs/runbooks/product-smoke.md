# Product smoke — полный контур NOVA CRM

> Сгенерировано из `SEED/smoke/product-smoke.md.example` (Witness Done v1.31.0).
> Канон: `catalogs/contour-smoke.md`. Каждая строка называет фразу приёмки — без неё акт
> `--gate product-smoke` не принимается.

## Когда

- Перед `sp-verify --gate pre_release` и promote на production.
- После деплоя на staging.
- Не на каждый D: для пачек — `scripts/smoke/wave-api-smoke.sh`.

## Предусловия

- [ ] staging frontend и API подняты, миграции применены, подписка `streaming`.
- [ ] Есть три тестовые учётные записи: постановщик, исполнитель, исполнитель без задач.
- [ ] MFA включена у всех тестовых пользователей (TOTP-секрет в менеджере секретов).
- [ ] Есть объект с задачами во всех пяти статусах и один архивированный объект.
- [ ] `API_TOKEN` staging доступен джобе smoke.

## Сценарии

| Фраза | Контур | Шаги | Ожидание |
|-------|--------|------|----------|
| A-S01.1 | health | `GET /health`, `GET /health/replication`, `/metrics` | 200, `status: streaming`, `lag_seconds` числом |
| A-S02.1 | вход | `/login` → пароль → TOTP | попадание на `/objects`, роль в шапке |
| A-S03.1 | вход без MFA | вход без второго фактора | отказ, сообщение без деталей |
| A-S04.1 | объекты | `/objects` → поиск → создание объекта | объект появляется в списке, счётчики 0 |
| A-S05.1 | карточка | `/objects/:id` → задачи объекта | задачи, статусные бейджи, пустое состояние при отсутствии |
| A-S06.1 | создание задачи | в объекте → «Новая задача» → назначить исполнителя | статус «Новая», история содержит запись создания |
| A-S07.1 | цикл | исполнитель: «В работу» → «На проверку» | статус меняется, история пополняется автором и временем |
| A-S08.1 | приёмка | постановщик: «Принять» | статус «Принята», переход доступен только постановщику |
| A-S09.1 | доработка | «Вернуть на доработку» без комментария → с комментарием | без комментария отказ; с комментарием статус «На доработке» + комментарий в истории |
| A-S10.1 | запрещённый переход | исполнитель пытается перевести «Новую» в «На проверке» | `P0422`, статус не изменился, истории нет |
| A-S11.1 | изоляция | исполнитель открывает чужую задачу по прямому URL | «нет доступа», данные не показаны |
| A-S12.1 | мои задачи | `/my-tasks` | только свои задачи, колонки по статусам, счётчики совпадают |
| A-S13.1 | архивирование | постановщик архивирует объект | объект исчезает из списка, задачи не видны, история сохранена |
| A-S14.1 | отчёты | `/reports` | три отчёта, `source: replica`, `lag_seconds`, нет email/описаний |
| A-S15.1 | деградация | остановить подписку (staging) | `/reports` показывает баннер, продукт работает, `/health/replication` = 503 |
| A-S16.1 | read-only backend | `POST /api/reports/objects` | `405`, данные не изменены |
| A-S17.1 | CSP | проверить заголовки production-сборки | `script-src 'self'`, без `unsafe-inline`/`unsafe-eval` |
| A-S18.1 | откат | Vercel Instant Rollback на staging | предыдущая версия открывается, `/health` = 200 |

## Внешние сервисы

| Сервис | CI | Staging smoke |
|--------|----|---------------|
| Supabase Auth | локальный GoTrue | живой staging-проект |
| Логическая репликация | service-контейнеры | живая подписка, лаг < 5 с |
| Grafana / Sentry | не требуются | проверка, что события доходят |
