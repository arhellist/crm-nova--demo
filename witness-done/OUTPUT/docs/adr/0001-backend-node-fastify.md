# ADR-0001: Backend на Node.js 20 + TypeScript strict (Fastify 4), только чтение

Дата: 2026-11-04

Статус: принят

## Контекст

ТЗ требует собственный backend, но оставляет только одну роль для него — отчётность с вторичной
БД. Запись и права обязаны оставаться в Supabase, иначе появляется второй источник правды.
Нужен язык, который: (а) тот же, что на фронтенде, чтобы один разработчик держал оба контура;
(б) имеет зрелую поддержку PostgreSQL и строгую типизацию; (в) даёт малый образ и быстрый старт.

## Решение

Backend — Node.js 20 LTS, TypeScript 5.5 (`strict: true`), Fastify 4, драйвер `pg`, валидация Zod,
логи pino. Образ собирается multi-stage, работает от непривилегированного пользователя, rootfs
read-only. Маршруты: `/health`, `/health/replication`, `/metrics`, `/api/reports/objects`,
`/api/reports/workload`, `/api/reports/status-ages`. Write-маршрутов нет; любой
`POST/PUT/PATCH/DELETE` возвращает `405`. В образе и окружении нет `service_role` и строки
подключения к primary.

## Рассмотренные альтернативы

- **Go** — лучше по памяти и старту, но второй язык в проекте и дублирование Zod-схем; для трёх
  отчётов выигрыш не оправдан.
- **Python (FastAPI)** — быстрый старт, но третий рантайм в CI и другой стиль типизации.
- **Полный API на Node поверх Supabase** — отвергнут: write-путь дублируется, RLS обходится,
  требование «права в БД» размывается.
- **Serverless-функции Supabase Edge** — нет контроля над окружением и `pg`-пулом, усложняет
  локальный контур и метрики.

## Последствия

Плюсы: один язык, один CI-образец, строгие типы на границах, предсказуемый Docker-контур,
физическое отсутствие пути записи. Минусы: Node требует больше памяти, чем Go; отчётный сервис
зависит от `pg`-пула и нуждается в healthcheck'ах. Дальше: реализовать маршруты с Zod-схемами
ответов, покрыть integration-тестами «write → 405» и «INSERT от `nova_ro` → 25006».

## Глоссарий

| Термин | Пояснение |
|--------|-----------|
| Fastify | веб-фреймворк для Node.js |
| pino | библиотека структурного логирования |
| rootfs read-only | файловая система контейнера только для чтения |
