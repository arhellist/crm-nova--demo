# ADR-0006: Три окружения, деплой и наблюдаемость

Дата: 2026-11-04

Статус: принят

## Контекст

KPI требуют доступности 99.9%, отката ≤ 15 минут и подтверждённого восстановления. Один контур и
ручной деплой этого не обеспечивают: невозможно проверить релиз до пользователей и невозможно
доказать готовность к инциденту.

## Решение

- **Окружения:** `local` (Supabase CLI + Docker), `staging` (отдельный проект Supabase и отдельные
  деплои frontend/backend), `production` (Supabase Cloud с PITR, Vercel, изолированный контур
  backend + реплика).
- **Релиз:** merge в `main` → зелёные джобы CI → автомиграции в staging → e2e/smoke → подтверждение
  через GitHub Environment → миграции в production → деплой frontend (Vercel, атомарно) → деплой
  backend тем же тегом образа → проверка `/health` и `/health/replication` → запись в журнал релизов.
- **Откат:** Vercel Instant Rollback и предыдущий Docker-тег; миграции forward-only, изменения схемы
  только добавляющие, поэтому откат кода не требует отката схемы.
- **Наблюдаемость:** Prometheus-метрики, дашборды и алерты Grafana Cloud; Sentry для ошибок;
  uptime-монитор из двух регионов; pino-логи с redact.
- **Данные:** ежедневные бэкапы (retention 30 суток) + PITR (окно 7 суток); учения восстановления
  не реже раза в квартал с записью в журнал; RTO ≤ 60 мин, RPO ≤ 5 мин.
- **Периметр:** Cloudflare — TLS, WAF, rate limiting, защита от ботов.

## Рассмотренные альтернативы

- **Один контур** — дешевле, но релиз проверяется сразу пользователями; KPI 9 и 8 недостижимы.
- **Kubernetes** — избыточен для двух контейнеров и одного разработчика.
- **Собственный Prometheus + Alertmanager на VPS** — требует дежурства; Grafana Cloud снимает
  эксплуатацию хранилища метрик.
- **Без PITR** — RPO становится «до последнего бэкапа» (сутки), что ломает KPI 8.

## Последствия

Плюсы: проверяемый релиз, быстрый откат, измеримые SLO, подтверждённое восстановление.
Минусы: стоимость Supabase-плана с PITR и Grafana Cloud; два набора секретов и проектов Supabase;
необходимость дисциплины миграций. Дальше: `docker-compose.yml`, CI-джобы, runbooks инцидента,
восстановления и ротации секретов, дашборды и правила алертов.

## Глоссарий

| Термин | Пояснение |
|--------|-----------|
| PITR | восстановление на произвольный момент времени |
| RTO / RPO | целевое время восстановления / целевая потеря данных |
| WAF | межсетевой экран веб-приложений |
| Instant Rollback | мгновенный откат деплоя на предыдущую сборку |
