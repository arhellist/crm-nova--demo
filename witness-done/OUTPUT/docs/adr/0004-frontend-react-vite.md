# ADR-0004: Frontend на React 18 + TypeScript strict + Vite, Tailwind по токенам референса

Дата: 2026-11-04

Статус: принят

## Контекст

Продукт — закрытая SPA: SEO и серверный рендеринг не нужны, зато важны быстрый старт, строгие типы
на границах с PostgREST/RPC и точное следование визуальному референсу (`INPUT/design/Design.html`).
Команда — один разработчик: чем меньше слоёв, тем ниже стоимость поддержки.

## Решение

React 18.3 + TypeScript 5.5 `strict: true`, сборка Vite 5, маршрутизация React Router 6, серверное
состояние TanStack Query 5 (никакого глобального state-менеджера), формы react-hook-form + Zod,
Tailwind CSS 3.4 с токенами из референса, примитивы Radix UI для доступности, lucide-react для
иконок, sonner для тостов. Тяжёлые UI-киты (MUI, AntD, Bootstrap) запрещены: конфликтуют с
референсом и раздувают бандл. Все ответы API и RPC валидируются Zod-схемами.

## Рассмотренные альтернативы

- **Next.js с SSR** — даёт SEO и серверные маршруты, но система закрытая; SSR добавляет Node-рантайм
  на периметре и усложняет CSP.
- **Vue/Svelte** — технически достаточны, но команда и LIBRARY-паттерны опираются на React.
- **Redux/MobX** — дублируют TanStack Query и увеличивают объём кода без выигрыша.
- **CSS-in-JS** — усложняет CSP (`style-src`), Tailwind работает с текущим `unsafe-inline` для стилей.

## Последствия

Плюсы: быстрый dev-цикл, строгие типы, минимальный бандл, прямое соответствие дизайну, инвалидация
кэша вместо ручной синхронизации состояния. Минусы: SPA требует SPA-rewrite на хостинге; доступность
обеспечивается вручную (Radix помогает, но не заменяет проверку). Дальше: каркас приложения,
дизайн-токены в CSS-переменных, общий `apiClient` с маппингом ошибок `P040x`.

## Глоссарий

| Термин | Пояснение |
|--------|-----------|
| SPA | одностраничное приложение |
| TanStack Query | библиотека кэширования серверного состояния |
| Zod | библиотека валидации схем |
