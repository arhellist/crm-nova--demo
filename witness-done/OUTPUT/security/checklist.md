# Security-чеклист перед релизом — NOVA CRM

> Сгенерировано Witness Done v1.31.0. Основа: OWASP ASVS 4.0.3 Level 2, OWASP Top 10:2021,
> OWASP API Security Top 10:2023. Каждый пункт проверяем: тест, конфиг или команда. Пункт без
> способа проверки не считается закрытым.

## V1. Архитектура и угрозы

- [ ] Модель угроз актуальна, остаточные риски перечислены (`security/threat-model.md`).
- [ ] Единственный путь записи (Supabase) подтверждён тестом: write в backend → `405`,
      `INSERT` от `nova_ro` → `25006`.
- [ ] `service_role` отсутствует в клиенте, образе, CI-логах (grep-гейт).
- [ ] ASVS отклонения зафиксированы в §9 этого файла с причиной.

## V2. Аутентификация

- [ ] Пароль ≥ 12 символов; проверка на утечки — политикой выдачи, а не самостоятельной регистрацией.
- [ ] Открытая регистрация отключена (`disable_signup = true`).
- [ ] TOTP MFA обязательна; вход без второго фактора невозможен (тест `aal1` → отказ).
- [ ] Защита от перебора: лимиты Auth + WAF + блокировка после 10 неудач за 10 минут.
- [ ] Восстановление пароля только через администратора, без email-ссылок.
- [ ] Ответы на неверный логин/пароль/код не различают причину.

## V3. Сессии и токены

- [ ] Access-токен 1 час, refresh с ротацией и reuse detection.
- [ ] Inactivity 7 дней, time-box 30 дней.
- [ ] `alg:none`, чужой `aud`/`iss`, истёкший и отозванный токен → `401` (тесты).
- [ ] `signOut global` работает; смена пароля и роли инвалидируют сессии.
- [ ] Токен не попадает в URL, логи, Referer, Sentry.
- [ ] Роль для доступа читается из `profiles`, а не из claim.

## V4. Контроль доступа

- [ ] RLS включён на `profiles`, `objects`, `tasks`, `task_status_history`.
- [ ] Политика для каждой операции (select/insert/update), политик «разрешить всё» нет.
- [ ] Исполнитель не читает и не меняет чужие задачи (IDOR/BOLA) — pgTAP + HTTP-тесты.
- [ ] `anon` не имеет ни политик, ни `execute` на RPC.
- [ ] Колоночные гранты не дают менять `tasks.status`, `tasks.author_id`, `profiles.role`.
- [ ] `security definer`-функции: `search_path` фиксирован, владелец `postgres`, `execute` только
      `authenticated`.
- [ ] Чужой ресурс отвечает так же, как несуществующий.

## V5. Валидация ввода и бизнес-логика

- [ ] Zod на всех границах: формы, ответы RPC/PostgREST, параметры отчётов, env.
- [ ] Ограничения длины и `CHECK` в БД дублируют UI-ограничения.
- [ ] Матрица переходов реализована в RPC и покрыта тестами на все 25 пар (6 разрешённых).
- [ ] `rework` без непустого комментария невозможен (RPC + `CHECK`).
- [ ] Смена исполнителя запрещена вне `new`/`rework`.
- [ ] Прямой `UPDATE status` отклоняется триггером (`P0403`).
- [ ] Физическое удаление невозможно: нет грантов `DELETE`, каскады `restrict`.

## V6. Криптография (делегирована)

- [ ] Собственный криптокод отсутствует (ASVS V6 delegated).
- [ ] TLS 1.2+ на всех внешних соединениях; HSTS включён.
- [ ] Секреты не хранятся в репозитории; `gitleaks` чист.
- [ ] Хеширование паролей и TOTP — на стороне Supabase Auth.

## V7. Обработка ошибок и логирование

- [ ] Ошибки наружу: только стабильные коды и человеческий текст; без SQL и stack trace.
- [ ] pino redact покрывает `authorization`, `cookie`, `apikey`, `password`, `*token*`.
- [ ] Sentry без PII (`sendDefaultPii: false`, `beforeSend`).
- [ ] События безопасности логируются: неуспешные входы, отказы RLS, `P0403/P0422`, смена роли.
- [ ] Логи не содержат тел запросов и значений полей.

## V8. Защита данных

- [ ] Публикация репликации не включает `auth.users`.
- [ ] Отчётные вьюхи без email/`description`/`comment`; тест на ключи ответа.
- [ ] Retention настроен и совпадает с `security/data-protection.md`.
- [ ] Бэкапы + PITR включены; учения восстановления проведены, запись в журнале.

## V9. Коммуникации

- [ ] HTTPS обязателен, HTTP редиректится.
- [ ] Security-заголовки: `Strict-Transport-Security`, `X-Content-Type-Options: nosniff`,
      `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`,
      `Permissions-Policy` с минимумом.
- [ ] CORS: allowlist, без `*` с credentials.
- [ ] TLS-сертификаты не отключены и не игнорируются в коде.

## V10. Вредоносный код и целостность

- [ ] CSP: `default-src 'self'; script-src 'self'; connect-src 'self' https://<ref>.supabase.co;
      style-src 'self' 'unsafe-inline'; img-src 'self' data:; frame-ancestors 'none';
      base-uri 'self'; form-action 'self'`.
- [ ] `unsafe-eval` отсутствует; `unsafe-inline` только в `style-src`.
- [ ] `dangerouslySetInnerHTML` не используется (grep-гейт).
- [ ] Сторонних скриптов, CDN-шрифтов и внешних iframe нет.
- [ ] `npm ci` по lockfile, `npm audit --audit-level=high` чист, Dependabot включён.

## V11. Бизнес-логика

- [ ] Повторный переход статуса не создаёт дубль истории.
- [ ] `archive_*` идемпотентны.
- [ ] Счётчики отчётов не могут быть подделаны клиентом: только чтение с реплики.
- [ ] Отчёт не отдаёт данные, недоступные пользователю по RLS (агрегаты только по видимым объектам
      компании; исполнитель отчёты не запрашивает — токен только у SPA руководителя).

## V12. API и файлы

- [ ] Rate limit 60/мин на токен, `429` при превышении.
- [ ] `API_TOKEN` обязателен для всех `/api/*`, `/metrics` — только внутренняя сеть.
- [ ] Методы кроме `GET` → `405`.
- [ ] Загрузки файлов отсутствуют (OUT OF SCOPE §2.2 ТЗ); проверка на отсутствие multipart-маршрутов.

## V13. Конфигурация

- [ ] Три окружения разделены, у каждого свои ключи.
- [ ] Prod-деплой требует подтверждения (GitHub Environment).
- [ ] Отладочные режимы (`debug`, verbose-логи, source maps с кодом) выключены в prod.
- [ ] `VITE_*` не содержит секретов.

## V14. Зависимости и CI

- [ ] `sp doctor --strict` зелёный.
- [ ] `sp rules --check` зелёный (адаптеры не разошлись с `AGENTS.md`).
- [ ] Все security-джобы обязательны для merge.
- [ ] Артефакты приёмки (`evidence/*.json`) приложены к релизу.

## §9. Отклонения от ASVS L2 (с причиной)

| Пункт ASVS | Отклонение | Причина | Компенсация |
|------------|------------|---------|-------------|
| V2.1.7 проверка пароля по базе утечек | не реализована | закрытая выдача паролей администратором | пароль генерируется, минимум 12 символов, смена при первом входе |
| V2.5.1 восстановление пароля по email | отсутствует | продуктовая граница: нет писем и самостоятельного восстановления | сброс администратором, журнал операций |
| V2.2.1 anti-automation CAPTCHA | не требуется | закрытая система, вход только для выданных учётных записей | rate limit + блокировка + MFA |
| V3.4.1 stateless JWT с немедленным отзывом | отзыв через Supabase (refresh-сессии) | платформенная реализация | TTL 1 час, `signOut global` |
| V6 криптография | делегирована Supabase Auth | запрет собственного криптокода | контракт платформы, отсутствие своего кода |
| V12 файлы | не применимо | файлы вне продукта (§2.2 ТЗ) | маршрутов загрузки нет |
| V13 антивирус | не применимо | нет загрузок | — |
| V9 mTLS внутри | не требуется | приватная сеть Docker без публикации портов | отдельная bridge-сеть |
