# Секреты и конфигурация — NOVA CRM

> Сгенерировано Witness Done v1.31.0. Правило: секрет живёт только там, где он нужен для работы,
> и нигде больше. Проверка — не «мы аккуратны», а гейт CI и ревью.

## 1. Инвентарь секретов

| Секрет | Где используется | Где хранится | Кто видит | Ротация |
|--------|------------------|--------------|-----------|---------|
| `VITE_SUPABASE_URL` | фронтенд | Vercel env (public) | все | при смене проекта |
| `VITE_SUPABASE_ANON_KEY` | фронтенд | Vercel env (public) | все (ключ публичен по дизайну) | при компрометации проекта |
| Supabase `service_role` | только локальный seed | локальный `.env.seed` + менеджер секретов | администратор | при подозрении; **никогда** не в Vercel/CI-логах |
| `SUPABASE_JWT_SECRET` | проверка токенов (платформа) | Supabase dashboard | никто из приложения | при компрометации, с инвалидацией сессий |
| `REPLICATOR_PASSWORD` | подписка на primary | менеджер секретов | контейнер `replica` | 90 дней |
| `NOVA_RO_PASSWORD` | чтение вторичной БД | менеджер секретов | контейнер `api` | 90 дней |
| `DATABASE_URL` (реплика) | API | менеджер секретов | контейнер `api` | при смене пароля |
| `API_TOKEN` | доступ к отчётам | менеджер секретов → env API и SPA-сборка | сервис + SPA | 90 дней, при увольнении |
| `SENTRY_DSN` | фронтенд и API | env | все (DSN не секрет, но PII-фильтр обязателен) | — |
| `GRAFANA_TOKEN` | агент/экспорт метрик | менеджер секретов | контейнер метрик | 90 дней |
| `CLOUDFLARE_API_TOKEN` | деплой/DNS | GitHub Environments | деплой-джоб | 180 дней |

## 2. Куда что кладём

| Окружение | Хранилище | Правила |
|-----------|-----------|---------|
| local | `.env.local` (не коммитится), Docker Compose env | только тестовые ключи, seed-данные |
| staging | GitHub Environments `staging` + Supabase project secrets | отдельный проект Supabase, отдельные ключи |
| production | GitHub Environments `production` (required reviewers) + Vercel env + Supabase secrets | доступ только через approve-джобу |

Ни один секрет не передаётся в клиент, кроме `VITE_*` с публичной природой. Префикс `VITE_`
запрещён для `service_role`, `API_TOKEN`, паролей БД и любых серверных ключей.

## 3. Что запрещено в git и логах

- Любые `.env*` кроме `.env.example` с пустыми значениями.
- Дампы БД, `pgdata/`, `.sql` с реальными данными.
- Токены и пароли в тестах и fixtures (только явно поддельные значения).
- Токены, cookies, `authorization`, `apikey`, `password`, `access_token`, `refresh_token` в логах
  (redact в pino, `beforeSend` в Sentry).
- Полные строки подключения с паролем в README, issue, CI-логах, сообщениях об ошибках.
- Скриншоты Supabase Studio с открытыми ключами.

## 4. Ротация

| Событие | Действия |
|---------|----------|
| Плановая (90 дней) | новый секрет → деплой → проверка health → отзыв старого |
| Увольнение сотрудника | блокировка в Supabase Auth, `signOut global`, ротация `API_TOKEN`, запись в журнал |
| Подозрение на утечку | немедленный отзыв, инвалидация всех сессий, проверка логов доступа, инцидент-репорт |
| Смена проекта Supabase | новые ключи, обновление Vercel/API, пересоздание подписки |

Порядок «сначала новый, потом отзыв старого» — чтобы не было окна отказа. Отзыв фиксируется
в журнале ротации (`docs/runbooks/secrets-rotation.md`).

## 5. Гейты CI

1. `gitleaks detect --no-git --redact` по рабочему дереву и истории PR.
2. grep-гейт: `service_role|SUPABASE_SERVICE|sb_secret` в `src/`, `dist/`, `docker/`, `Dockerfile*`
   → провал.
3. `npm audit --audit-level=high` (frontend и backend).
4. Проверка, что в бандле нет `DATABASE_URL` и `REPLICATOR_PASSWORD` (поиск по `dist/assets/*.js`).
5. Проверка CSP-заголовков на preview-деплое.
6. `sp doctor --strict` — правки вне маршрута и `done` без акта.

## 6. Конфигурация приложения (не секреты)

| Переменная | Назначение | Значение по умолчанию |
|------------|------------|-----------------------|
| `API_BASE_URL` | адрес отчётного API | `http://127.0.0.1:8080` локально |
| `REPORT_CACHE_TTL_MS` | кэш отчётов в процессе | `30000` |
| `REPLICA_LAG_ALERT_SECONDS` | порог деградации | `30` |
| `DB_POOL_MAX` | размер пула `pg` | `10` |
| `LOG_LEVEL` | уровень pino | `info` (в prod), `debug` (локально) |
| `ALLOWED_ORIGINS` | allowlist для API | локально `http://localhost:5173` |

Конфигурация валидируется Zod при старте: отсутствие обязательной переменной — падение процесса
с понятным сообщением, без вывода значения.
