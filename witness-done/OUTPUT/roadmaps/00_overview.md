# Roadmap — обзор (весь P0 IN SCOPE)

> Создан на шаге 09. Весь объём — это полная поставка; S0…S10 — **порядок работ и проверяемые
> срезы**, а не «версии готовности» (`catalogs/completeness-policy.md`).
> Статусы — в `progress.md`. Нарезка — в `d-cut-list.md`.

## Что входит

Весь IN SCOPE `INPUT/TECH_SPEC.md` §2: вход с MFA и сессией, две роли из БД, объекты (список,
создание, правка, архивирование, карточка), задачи (создание, правка, архивирование, назначение,
карточка), цикл из 5 статусов и 5 переходов с проверкой в БД, неизменяемая история, экраны входа,
объектов, объекта, задачи, «Мои задачи», отчётов и 404, RLS + RPC, seed-данные, read-only backend
с health-эндпоинтами, логическая репликация с контролем лага, ASVS L2, эксплуатация и документация.

OUT OF SCOPE (файлы, переписка, уведомления, UI-управление пользователями, мобильное приложение,
мультитенантность, поиск, BI) — `improvement-backlog.md`, без D.

## Порядок и зависимости

`D01 → D02 → D03 → D04 → D05 → D06 → D07 → D08 → D09 → D10 → D11 → D12 → D13 → D14`.
Рёбра и обоснования — `dependency-graph.md`. Параллелить можно только пары, где нет ребра:
D05/D06 после D02; D10 после D03; D11 после D10.

## Критерий закрытия среза

1. Все D среза `done` в `progress.md` с `evidence_ref` и непустым `acceptance_ids`.
2. Wave smoke `scripts/smoke/wave-api-smoke.sh <split_group>` зелёный.
3. test-plan каждого D без строк вне `covered`/`ops`.
4. Нет `proof_debt` и нарушений `PRODUCES`.

## Не входит в этот прогон

- Второй путь записи (backend write) — запрещён инвариантами `INV-004`, `INV-011`.
- Failover реплики: реплика read-only и не претендует на HA (ADR-0003).
- Мобильный клиент: `blocked_adr` (ADR-0007), будущие D — в `improvement-backlog.md`.
