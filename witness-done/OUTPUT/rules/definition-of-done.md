# Definition of Done — NOVA CRM

> Действует для каждого задания `Dxx` и каждого пакета изменения. Пункт, который нельзя проверить,
> не считается выполненным.

## Контракты

- [ ] Реализованы ровно `PRODUCES` задания; изменённых файлов вне списка нет.
- [ ] Публичные контракты (RPC, эндпоинты, типы ответов) совпадают с `OUTPUT/specs/*`.
- [ ] Все ошибки имеют стабильные коды (`P0403`, `P0422`, `P0400`, `E_INTERNAL`) и человеческий
      текст для пользователя; детали не утекают наружу.

## Права и данные

- [ ] Для каждой новой таблицы/колонки есть RLS-политика или явный отказ; `anon` не читает ничего.
- [ ] Переходы статусов идут только через `rpc.change_task_status`; история пополняется триггером.
- [ ] Роль читается из `profiles.role`; claim `role` в JWT не используется для решений о доступе.
- [ ] `service_role` отсутствует в клиенте, backend, образе и логах.
- [ ] Схема меняется только миграцией в `supabase/migrations/`.

## Тесты

- [ ] Unit-тесты покрывают новую логику; для SQL — pgTAP-тесты RLS и переходов.
- [ ] Каждая фраза `Axx.k` объявлена тестом (`@acceptance Axx.k` или ID в имени); `skip` отсутствует.
- [ ] Негативные кейсы есть: чужая сущность, запрещённый переход, отсутствие прав, пустые данные.
- [ ] `npm run lint`, `npm run typecheck`, `npm run test` — зелёные, ошибок 0, предупреждений нет.
- [ ] `sp verify <Dxx> --gate pre_ci` → `tax_pass: true`, акт `OUTPUT/evidence/<Dxx>.json`.

## Безопасность

- [ ] JWT/MFA/RBAC/CSRF-требования затронутой области выполнены (§8 ТЗ), проверка — тестом.
- [ ] Ввод валидирован Zod на границе; SQL параметризован; динамического SQL нет.
- [ ] Токены и PII не попадают в логи, URL и аналитику.
- [ ] CSP и security-заголовки не ослаблены.

## Продукт и UI

- [ ] UI следует `OUTPUT/docs/design-notes.md`; состояния загрузки/пустоты/ошибки реализованы.
- [ ] Работа с клавиатуры, `aria`-подписи, контраст ≥ 4.5:1, адаптив 360/768/1440.
- [ ] Действия, недоступные роли, не отображаются, но их отсутствие не является защитой.

## Документация и прогресс

- [ ] Комментарии в коде на русском, объясняют «зачем» и инварианты, а не пересказывают строки.
- [ ] `progress.d/<Dxx>.md` обновлён, `sp progress --merge` выполнен.
- [ ] Решения, принятые по ходу, записаны через `sp decide` до кода.
- [ ] При изменении контрактов обновлены `specs/` и, при необходимости, ADR.
