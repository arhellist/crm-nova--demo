# Политика входного дизайна (опциональный HTML)

> Канон Witness Done (правило действует с v1.7). Визуальный стиль продукта берётся из **переданного дизайна**, а не из «дефолтного AI UI».

## Вход (опционально)

Положи в проект фабрики один из вариантов:

| Путь | Назначение |
|------|------------|
| `INPUT/DESIGN.html` | Один файл — референс экрана / лендинга / UI kit |
| `INPUT/design/*.html` | Несколько экранов (home, place, cart…) |
| `INPUT/design/.gitkeep` | Пустой каталог-заглушка: сюда кладут HTML |

Примеры (не вход проекта): `TEMPLATES/examples/DESIGN.example.html`. Копировать его в `INPUT/` не нужно — это образец формы, а не дизайн.

Если файлов **нет** — в MANIFEST: `design_input: none`; UI-D опираются на ТЗ §9 + разумный минимальный UI **без** выдумывания чужого брендбука.

Если файлы **есть** — `design_input: present` и шаг 01/02/09 **обязаны** учесть дизайн.

## Что делает фабрика (не код продукта)

1. **Шаг 01** — зафиксировать наличие дизайна; gaps («только лендинг / нет кабинета»).
2. **Шаг 02/03** — в constitution/architecture: «UI следует `OUTPUT/docs/design-notes.md`».
3. **Шаг 02 или 08** — создать:
   - `OUTPUT/docs/design-notes.md` — извлечённые токены и правила;
   - при возможности `OUTPUT/docs/design-inventory.md` — список экранов из HTML.
4. **Шаг 09** — все UI-связанные D: CONSUMES на `design-notes.md`; в ОГРАНИЧЕНИЯХ — не менять палитру/типографику/радиусы без пометки.

## Что извлечь из HTML (минимум)

| Категория | Примеры |
|-----------|---------|
| Цвет | background, surface, text, accent, border, danger |
| Типографика | font-family, размеры H1–body, weight |
| Spacing | базовый шаг (4/8), отступы секций |
| Радиусы / тени | button, card |
| Компоненты | кнопки, инпуты, карточки, навбар — как в HTML |
| Breakpoints | mobile-first правила из media queries |
| Тон | плотный/воздушный, «карточки да/нет» |

Идентификаторы в коде — английские (`--color-accent`). Проза в design-notes — **русская**.

## Правила для агента разработки

- Не подменять дизайн на «типичный SaaS» (фиолетовые градиенты, random cards), если передан HTML.
- Допустимо адаптировать под React/Next/компоненты, **сохраняя** токены и иерархию.
- Если HTML конфликтует с accessibility — зафиксировать отклонение в design-notes + ADR/minor note.
- SEO SSR-страницы тоже в том же визуальном языке.

## Чего фабрика не делает

- Не клонирует HTML один-в-один без семантики.
- Не требует Figma (HTML — достаточный опциональный вход; Figma-ссылка может быть в ТЗ §13 как дополнение).
