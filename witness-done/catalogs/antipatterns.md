# Каталог антипаттернов ИИ (v1)

Используй на шагах анализа, ассемблеи и в каждом dev-промпте: «проверь по `catalogs/antipatterns.md`».

## Скоуп и полнота

- **Ярлык неполноты** вместо объёма: «MVP», «PoC», «beta», «пока без авторизации», «упрощённая
  версия» — режет целевую комплектацию; лечится полным IN SCOPE или явным OUT OF SCOPE с причиной
  (`catalogs/completeness-policy.md`)
- **`v1` как статус готовности** вместо объёма: `v1` — весь IN SCOPE, порядок работ — `S0…S8`
- D «на будущее» под ярлыком `LATER`: место отложенного — `improvement-backlog.md`, а не D-промпт
- «Заглушка» в specs без ADR: скрытое незакрытое требование

## Данные / SQL

- N+1 в циклах (нужен JOIN / batch / DataLoader)
- OFFSET-пагинация на больших таблицах без необходимости
- Динамический ORDER BY без whitelist → SQL injection
- Несколько связанных записей без транзакции
- Отсутствие индексов под фильтры списка и FK
- Хранение секретов / сырых токенов без хеша

## API

- Разные error envelopes в разных эндпоинтах
- Утечка внутренних ошибок в production response
- Нет идемпотентности на критичных POST (платежи, создание заказа)
- AuthZ только на UI, без проверки на сервере
- Breaking changes без версионирования контракта

## Frontend

- Мутация state напрямую
- Пропущенные зависимости в hooks
- Дублирование refresh/retry без очереди (thundering herd)
- Секреты / токены в localStorage при httpOnly-стратегии
- Оптимистичный UI без отката при ошибке
- App-код на plain JS вместо TypeScript

## Типы и тесты

- `any` / отключение strict без причины
- Untyped границы JSON/env без Zod (или аналога)
- Новая логика без автотестов в том же PR/изменении
- `progress` → `done` при красных или отсутствующих тестах
- Тест на фразу `Axx.k` без объявления фразы (`@acceptance`/ID в имени) — `pre_ci` не найдёт связь
- Тест, объявивший фразу, но без утверждения (`it('A01.1', () => save())`) — пустая связь
- `it.skip('A01.1 …')` как «покрытие»: пропущенный тест не закрывает фразу
- Ссылка на `Axx.k`, которого нет в ACCEPTANCE задания, — тест и таблица разошлись
- Переписанная формулировка фразы после приёмки без нового `pre_ci` — акт устарел (`binding_hash`)
- План `test-plan-Dxx.md`, где строка названа «напишем позже» и `--gate acceptance` не гоняли

## Общее

- Псевдокод вместо рабочего кода в «финальных» шагах
- Код без подробных комментариев на публичные API / нетривиальные ветки (`catalogs/code-comments.md`)
- Шумовые комментарии, дублирующие следующую строку кода
- Переписывание файлов вне PRODUCES
- Игнорирование OUT OF SCOPE
- «Сделаю потом» для ошибок и граничных случаев
- Генерация всей фичи одним куском без контрактов

## Как расширять

После каждого реального бага ИИ добавь сюда 1 строку. Не раздувай мета-промпты — ссылайся на каталог.
