# Бизнес-цели — основа ТЗ

> Канон Witness Done (правило действует с v1.11). Вшивается в `INPUT/TECH_SPEC*`, `INPUT/ANSWERS.md`, шаг **01**, completeness, assembly.  
> Цель: не начинать архитектуру, SEO, маркетинг и нарезку D «с фич», пока не ясны **зачем продукт бизнесу** и **как измерить успех**.

## Принцип

```text
Бизнес-цели / KPI  →  ценность для пользователя  →  сценарии P0  →  IN SCOPE
                                                              ↓
                                    маркетинг / SEO / контент / монетизация
                                                              ↓
                                    стек, NFR, модули, D-цепочка
```

SEO, лендинги, аналитика, тарифы, админка — **следствия** целей, не самостоятельный «список фич».

## Что обязано быть в ТЗ (или в ANSWERS после 01)

| Тема | Вопросы (минимум) |
|------|-------------------|
| Цель бизнеса | Зачем продукт существует через 12–24 мес? (выручка, лиды, экономия, доля рынка, внутренний процесс) |
| Клиент / сегмент | Кто платит vs кто пользуется? B2B / B2C / internal |
| Ценность | Какую боль снимаем? Чем лучше альтернативы? |
| Успех (KPI) | 3–7 измеримых метрик v1 (не «удобный UI») |
| Монетизация | Как зарабатываем / экономим? Что **не** монетизируем в v1 |
| Go-to-market | Как узнают о продукте? SEO / ads / sales / partnerships — приоритет |
| Конкуренты | 1–3 аналога и отличие |
| Анти-цели | Чего сознательно **не** оптимизируем в v1 |

## Правила для шага 01

1. Секция **«Бизнес-цели и успех»** в `01_analysis.md` — **первая** содержательная после резюме.
2. Группа вопросов **Business** в `01_questions.md` и `ANSWERS.md` — **перед** Product/Tech.
3. Нет ясности по цели бизнеса + KPI успеха → `needs_human` (не менее критично, чем «кто пользователь»).
4. Нельзя принять default «сделаем маркетплейс/CRM/лендинг» без привязки к KPI.
5. Черновик срезов (D-cut) и LIBRARY: помечай, **какую бизнес-цель** закрывает срез (колонка или заметка).

## Правила для шагов 03–09

- ADR и module plan: фича без связи с бизнес-целью / KPI → вопрос или `later`, не silent IN SCOPE.
- SEO / SSR / контент / аналитика: только если цель/GTM это требует (или явный IN SCOPE с KPI).
- Coverage-matrix: P0 сценарии трассируются к бизнес-целям, не только к § фич ТЗ.
