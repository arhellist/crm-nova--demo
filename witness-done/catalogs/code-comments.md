# Политика комментариев в коде

> Канон Witness Done v1.9.1+. Вшивается в constitution (02), `.cursorrules`, D-промпты (09), аудит (10).  
> При написании/изменении кода агент **обязан** оставлять подробные комментарии — не «только неочевидное».

## Правило

1. **Язык комментариев — русский** (как документация фабрики). Идентификаторы кода — английские.
2. Каждый **новый/изменённый** модуль, публичная функция/метод, класс, React-компонент, route handler, worker — с блоком «зачем / контракт / важные ветки».
3. Нетривиальные блоки внутри функции (authz, транзакции, идемпотентность, ретраи, парсинг, маппинг статусов, edge cases) — поясняющий комментарий **перед** блоком.
4. Миграции / SQL / конфиг с побочными эффектами — зачем изменение и на что влияет.
5. Тесты: кратко **что** проверяет кейс (можно в `it`/`test` description + комментарий к сложной фикстуре).

## Минимум по типу символа

| Что | Комментарий |
|-----|-------------|
| Файл / модуль | 2–5 строк в шапке: роль в системе, границы (что не делает) |
| `export` function / method / class | JSDoc-подобный блок: назначение, параметры, возврат, ошибки/побочные эффекты |
| Route / controller action | Какой контракт OpenAPI, какие роли AuthZ |
| Доменная ветка (`if status…`) | Почему ветка и ссылка на правило (статус из data-model) |
| Обход CONFLICTS / platform hook | Явная пометка (logging, rate-limit, и т.п.) |

Пример формы (TS):

```ts
/**
 * Создаёт заказ в статусе draft.
 * AuthZ: только владелец cartId. При гонке — 409, без частичной записи.
 * @param input — уже провалидированный Zod DTO
 */
export async function createOrder(input: CreateOrderDto): Promise<Order> {
  // Идемпотентность: повтор с тем же Idempotency-Key возвращает тот же orderId
  …
}
```

## Запрещено (шум)

- Комментарии, дублирующие очевидную строку кода один-в-один: `// увеличиваем i`, `// return result`
- Закомментированный мёртвый код «на всякий случай»
- TODO без номера D / ticket и критерия закрытия
- Английские простыни без нужды, если команда ведёт docs на русском
