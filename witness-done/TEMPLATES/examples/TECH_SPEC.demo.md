# ТЕХНИЧЕСКОЕ ЗАДАНИЕ ПРОЕКТА (DEMO)

> Демо для прогона фабрики / golden path. Не боевой продукт.

## 0. Бизнес-цели и успех

- **Цель бизнеса (12–24 мес):** учебный прогон Witness Done; «продукт» — демо API задач
- **Кто платит vs кто пользуется:** internal (автор фабрики) / B2C-имитация пользователей демо
- **Ценность для пользователя:** быстрый CRUD задач после логина
- **KPI успеха v1:** фабрика доходит до READY; 3 P0-сценария закрыты тестами; время прогона фабрики приемлемо
- **Монетизация:** нет (демо)
- **Go-to-market:** нет SEO/ads; канал = локальный прогон
- **SEO / маркетинг в v1:** OUT OF SCOPE (нет GTM-цели)
- **Конкуренты:** todo-demo apps; отличие — служит тестом фабрики
- **Анти-цели v1:** не масштабирование, не монетизация, не SEO

## 1. Название и суть

- **Название проекта:** Demo Tasks API
- **Одной фразой:** Простой API задач с логином и списком задач
- **Для кого:** individual users (B2C)
- **Проблема:** нужен учебный/демо backend+SPA для проверки Witness Done
- **Связь с §0:** закрывает KPI «фабрика + 3 P0 сценария»

## 2. Границы

- **IN SCOPE:** регистрация/логин, CRUD задач (title, done), пагинация списка
- **OUT OF SCOPE:** платежи, чат, админка, поиск ES, upload, SEO
- **Позже:** шаринг задач, уведомления

## 3. Стек

- **Frontend:** React 18 + Vite + TypeScript
- **Backend:** Node 20 + Express
- **БД:** PostgreSQL + Sequelize
- **Очереди / кэш:** нет в v1
- **Хостинг:** локально / любой VPS
- **Архитектурный стиль:** модульный монолит

## 4. Ключевые сценарии

1. Пользователь регистрируется и входит
2. Создаёт/редактирует/удаляет свои задачи
3. Фильтрует по done + пагинация

## 5. Сущности

| Сущность | Поля | Связи |
|----------|------|-------|
| User | id, email, passwordHash, timestamps | 1—N Task |
| Task | id, userId, title, done, timestamps | N—1 User |
