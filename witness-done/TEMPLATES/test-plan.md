# test-plan Dxx — чеклист приёмки, с которым сверяется машинный гейт

> Шаблон для `OUTPUT/tests/test-plan-Dxx.md`. Пишется на шаге 09 вместе с D-промптом (C3).
> `sp-verify --gate acceptance --d Dxx` читает таблицу и сверяет её с исходниками тестов:
> план не может назвать тест, который фразу не объявляет, и не может пропустить фразу
> (DEC-027, `catalogs/verification-tax.md`).

## Как заполнять

- Строка на каждую фразу `## ACCEPTANCE` задания. ID — точно как в промпте (`A01.3`).
- Колонка «Тест» — путь к файлу из `PRODUCES` (можно `tests/x.test.ts::имя теста`).
  Тот же файл обязан объявлять фразу (`@acceptance A01.3` или ID в имени теста).
- «Статус» — `covered` (исполняемый тест), `ops` (внешний контур; фраза перечислена
  в `FIT_CHECKS → acceptance_ops`), `blocked` (не закрыто — гейт валит).
- Фраза, которую проверяет только внешний контур, всё равно занимает строку: молчаливого
  исключения нет.

## Таблица

| ID | Фраза | Тест | Статус |
|----|-------|------|--------|
| Axx.1 | … | `tests/…` | covered |
| Axx.2 | … | `tests/…` | covered |
| Axx.3 | … | `tests/…::имя теста` | covered |
| Axx.4 | … | `scripts/smoke/…` | ops |

## Что проверяет гейт

1. Строка есть для каждой фразы ACCEPTANCE и нет строк для фраз, которых в задании нет.
2. Указанный тест существует в `PRODUCES` и объявляет тот же ID.
3. Указанный тест содержит утверждение и не пропущен.
4. Статус не `blocked`/`todo`/`—`.

Чего гейт не делает: не проверяет, что тест проверяет смысл фразы. Это читает ревьюер
(`sp review Dxx`), и в отчёте это написано прямо.
