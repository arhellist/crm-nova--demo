# Журнал проекта

Журнал входа и решений Witness Done. **Коммитится**: это источник правды о том, что просили и почему
сделали именно так. `pull` приносит чужие решения, `push` делает твои видимыми.

```
journal/
├── intake/        записи входа: запрос дословно, классификация, маршрут next:
├── decisions/     по одному файлу на DEC-###: контекст, решение, альтернативы, чем подтверждено
└── decisions.md   оглавление — собирается из decisions/, руками не правится
```

## Правила

1. **Одна запись — один файл.** `intake/<ID>.md`, `decisions/DEC-###-<slug>.md`. Параллельные ветки
   не конфликтуют: у каждой свой файл.
2. **`decisions.md` — производный вид.** Конфликт в оглавлении лечится `sp journal --index`,
   а не разрешением маркеров. Если включён `merge=union` в `.gitattributes`, дубли строк тоже
   исчезают пересборкой.
3. **`DEC-###` не переиспользуется.** Номер выдаёт `sp decide` — с учётом `origin/main`, поэтому
   две ветки не получат один номер. Переименование — `sp decide --renumber`.
4. **Append-only.** Принятое не переписывается: изменившееся решение — новое `DEC-###` со ссылкой
   `Заменяет`.
5. **Решение принимается до кода.** `sp decide` вызывается до первой правки, а не после.

## Команды

```bash
sp journal            # что в журнале: последние решения и открытые записи входа
sp journal --index    # пересобрать decisions.md из decisions/
sp journal --check    # дубли номеров, битые ссылки, дрейф индекса (exit 2 на проблемах)
sp journal --list     # последние N записей входа и решений
sp journal --migrate  # перенести старый журнал из OUTPUT/ в journal/
```

## Что здесь пусто и почему

Поставляется пустым: заголовки без записей. Заполненные примеры в шаблоне означали бы, что в новый
проект приехали чужие решения. Первая запись появится после `sp intake`.
