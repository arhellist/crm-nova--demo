# DEC-036 — Локальный seed обязан полностью воспроизводить staging-вход: пустые токены по…

| Поле | Значение |
|------|----------|
| Дата | 2026-11-04 |
| Intake | — |
| Статус | принято |
| ADR | — |
| Заменяет | — |

**Контекст.** `supabase db reset` удаляет `auth.mfa_factors`, после чего локальный стенд перестаёт воспроизводить вход с MFA: setup падает, A14.1 01 не выполняется. Стенд обязан подниматься из нуля одной командой и сохранять тот же сценарий, что production.

**Решение.** Локальный seed обязан полностью воспроизводить staging-вход: пустые токены подтверждения вместо NULL (GoTrue падает на NULL), строки auth.identities для email-провайдера и TOTP-фактор менеджера с детерминированным локальным секретом. Без MFA-фактора supabase db reset оставлял manager без второго фактора, и сценарии A14.1/A04.1 падали после сброса стенда.

**Альтернативы.** Создавать фактор через Auth API в `global-setup.ts` — отвергнуто: добавляет скрытое состояние и второй парольный вход в подготовку. Отключать MFA на стенде — отвергнуто: приёмка A14.1 проверяет именно второй фактор.

**Чем подтверждено.** `supabase/seed.sql` вставляет фактор с детерминированным секретом; e2e A14.1 01 проходит после `db reset`; runtime-гейт D14 поднимает стенд с нуля и получает `tax_pass: true`.
