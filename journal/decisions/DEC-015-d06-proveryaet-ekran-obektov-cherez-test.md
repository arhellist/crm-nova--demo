# DEC-015 — D06 проверяет экран объектов через Testing Library с моками модуля контракта …

**Контекст.** ОГРАНИЧЕНИЯ D06 предписывают «Testing Library + MSW», но MSW нет в стеке проекта
(D01 фиксировал зависимости), а HTTP-граница PostgREST уже покрыта тестами D05: коды ошибок,
keyset-курсор и валидация ответа запечатаны в `api.test.ts`/`authz.test.ts`. Для D06 проверяется
поведение UI: роль, пагинация, пустое состояние, архивная карточка. Дополнительно HOW п.2 требует
поиск только по загруженным страницам, то есть фильтр не должен порождать запросы.

**Решение.** D06 проверяет экран объектов через Testing Library с моками модуля контракта D05 (listObjects/getObject/archiveObject), а не через MSW: HTTP-поведение PostgREST уже запечатано тестами D05, а MSW отсутствует в стеке и добавил бы зависимость ради дублирования. Ключ бесконечного запроса не содержит строку поиска — фильтр локальный по загруженным страницам, иначе каждый символ вызывал бы сетевой запрос.

**Альтернативы.** (1) Поставить MSW и мокать сеть — новая зависимость и дублирование уже
запечатанного контракта D05. (2) Мокать `fetch` вручную — тот же дубль, но без типизации.
(3) Включить строку поиска в ключ `useInfiniteQuery` — сетевой запрос на каждый символ и сброс
загруженных страниц. Принято: моки модуля контракта `./api.js`/`./mutations.js`, локальный фильтр,
ключ без `q`.

**Чем подтверждено.** `src/features/objects/useObjects.ts` (ключ `objectKeys.list`, фильтр в
`useMemo`), `src/features/objects/*.test.tsx` с `vi.mock`; 34 теста зелёные, `sp verify --d D06
--gate pre_ci` = `tax_pass: true`.
