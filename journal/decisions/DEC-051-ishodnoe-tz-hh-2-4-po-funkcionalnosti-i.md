# DEC-051 — Исходное ТЗ hh (§2–§4) по функциональности и безопасности закрыто рабочей дем…

**Контекст.** Пользователь прислал исходное тестовое ТЗ с hh.ru (мини-CRM «Объекты и
задачи»). Нужна сверка сдачи с ним, а не с расширенным `INPUT/TECH_SPEC.md` WitnessDone.

**Решение.** Исходное ТЗ hh (§2–§4) по функциональности и безопасности закрыто: демо
`https://arhellist.ru/crm-nova/`, seed-доступы (1 постановщик + 2 исполнителя, объекты и
задачи во всех статусах), миграции + README, объяснение в README §8, список решений в
`docs/decisions.md`. Отличия от буквы hh: hard-delete заменён архивированием; у
постановщика — TOTP; сверх ТЗ — отчёты/реплика/read-only API. Перед отправкой на hh
проверить доступ заказчика к `origin` (`arhellist/WitnessDone`) и выдать TOTP-секрет
менеджера.

**Альтернативы.** Считать «не закрыто», пока нет hard-delete и нет отчётов в hh — отвергнуто:
архив сильнее требования безопасности hh §3; отчёты — расширение, не пробел. Переписывать
продукт под 2–3 часа «минималку» — отвергнуто: уже есть рабочая сдача большего объёма.

**Чем подтверждено.** Матрица переходов §2.3 в RPC/триггерах; RLS §3; демо-URL; seed;
README §8; `docs/decisions.md`; DEC-048/049 (демо + отчёты).
