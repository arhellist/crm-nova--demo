# DEC-019 — История задачи читает актора из task_status_history.changed_by, а не actor_id…

| Поле | Значение |
|------|----------|
| Дата | 2026-11-04 |
| Intake | — |
| Статус | принято |
| ADR | — |
| Заменяет | — |

**Контекст.** HOW D08 п.1 перечисляет поле истории `actor_id`, но `data-model.md` §3.4 и миграция D02
называют колонку `changed_by`. Запрос с несуществующей колонкой PostgREST отклонит, а подмена
имени в коде без записи решения скрыла бы расхождение контрактов.

**Решение.** История задачи читает актора из task_status_history.changed_by, а не actor_id из HOW D08: в data-model §3.4 и в таблице D02 колонка называется changed_by. Запрос остаётся только на чтение, запись по-прежнему делает триггер.

**Альтернативы.** (1) Использовать `actor_id` и добавить колонку-синоним в БД — изменение схемы вне D08 и дубль
смысла. (2) Переименовать `changed_by` — ломает триггеры D03 и аудит. (3) Читать `changed_by`
из спецификации — принято; маппинг в UI-модель `TaskHistoryRow.changed_by` совпадает с БД.

**Чем подтверждено.** `src/features/tasks/useTask.ts` (select `changed_by`), `A08.6` в `src/features/tasks/TaskPage.test.tsx`;
`data-model.md` §3.4.
