# DEC-028 — D13: дашборд Grafana по HOW должен содержать панели длительности переходов и …

| Дата | 2026-11-04 |
| Intake | — |
| Статус | принято |

| Заменяет | — |

**Контекст.** HOW D13 требует панели «длительность переходов» и «размер WAL». Длительность
переходов продукт не эмитит ни в одну серию: `change_task_status` идёт через Supabase RPC,
а не через backend. Размер WAL живёт на primary, к которому read-only backend не имеет
доступа (INV-001, ADR-0003). Добавить панели можно только с выдуманной или недоступной
метрикой — такие панели всегда пустые и маскируют отсутствие наблюдаемости.

**Решение.** D13: дашборд Grafana по HOW должен содержать панели длительности переходов и размера WAL, но в контуре продукта таких метрик нет: backend только читает реплику (INV-001) и не видит WAL primary, а длительность переходов не эмитится в Prometheus. Дашборд собирается только из реально существующих серий (/metrics D11 + up); WAL и переходы остаются вне панелей до появления экспортёра, зафиксировано в runbook как известное ограничение наблюдаемости.

**Альтернативы.** Подключить Postgres-exporter к primary — новый сервис и доступ к primary,
требует ADR и выходит за PRODUCES. Считать «длительность перехода» из `report_status_ages`
через Postgres datasource — другой источник, чем заявленный Prometheus, и не даёт p95
по маршрутам. Оставить фиктивные `nova_wal_bytes`/`nova_transition_seconds` — запрещено
инвариантом 1 (каждая метрика правил существует в `/metrics`). Принят дашборд только
по реальным сериям; ограничение записано в `docs/runbooks/incident.md`.

**Чем подтверждено.** `observability/rules.test.mjs` (все серии панелей и правил входят
в набор `/metrics` D11 и `up`; JSON дашборда валиден), `A13.1`/`A13.2`,
`observability/grafana/dashboard.json`, `docs/runbooks/incident.md` раздел «Ограничения».
