# DEC-016 — D07 принимает description до 5000 символов, как в domain-rules §9 и data-mode…

| Поле | Значение |
|------|----------|
| Дата | 2026-11-04 |
| Intake | — |
| Статус | принято |
| ADR | — |
| Заменяет | — |

**Контекст.** HOW D07 п.2 ограничивает `description` 2000 символами, а `domain-rules.md` §9 и `data-model.md`
§3.3 задают 5000 (и БД допускает ровно 5000). Два контракта расходятся, и выбор влияет на
валидацию формы D08 и на текст ошибки.

**Решение.** D07 принимает description до 5000 символов, как в domain-rules §9 и data-model §3.3, а не 2000 из HOW: спецификация выше задания. Комментарий перехода остаётся 2000 — это отдельное поле истории.

**Альтернативы.** (1) Взять 2000 из HOW — клиент отклонит текст, который БД принимает, и сузит домен без
изменения ТЗ. (2) Взять 5000 из спецификации — принято: `OUTPUT/specs/*` выше промпта (§1.5).
Комментарий перехода остаётся 2000, это отдельное поле `task_status_history`, а не описание.

**Чем подтверждено.** `src/features/tasks/schema.ts` (`description` max 5000), `src/features/tasks/schema.test.ts`
(A07.5); `sp verify --d D07 --gate pre_ci` = `tax_pass: true`.
