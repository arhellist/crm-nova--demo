# DEC-035 — D02/D05/D06: objects_select разрешает manager читать архивные объекты, исполн…

**Контекст.** Приёмка A06.5 требует открыть архивный объект по ID, а политика `objects_select` отдавала менеджеру только строки с `archived_at is null`. Архивный объект исчезал из выдачи, хотя архивирование — штатная операция D03 и продукт обязан показывать архив (INV-002: права решает БД, а не фильтр в UI).

**Решение.** D02/D05/D06: objects_select разрешает manager читать архивные объекты, исполнителю архивные по-прежнему не видны. Причина: D05 п.8 требует читаемости архивного объекта, D06 A06.4/A06.5 — бейдж «Архив» и карточку с задачами; политика 0003 отсекала архивные для всех ролей, из-за чего фильтр «Показать архивные» был мёртвым. Список по умолчанию остаётся без архивных (archived_at=is.null в запросе).

**Альтернативы.** Оставить политику и прятать архивные строки в интерфейсе — отвергнуто: тогда архив недоступен и A06.5 невыполним. Отдельный RPC для чтения архива — отвергнуто: расширяет API без причины, RLS уже различает роли.

**Чем подтверждено.** Миграция `supabase/migrations/0010_objects_select_archived_manager.sql`; pgTAP `supabase/tests/rls_test.sql`; e2e A14.1 11 «менеджер архивирует объект»; runtime-гейт D14 (`tax_pass: true`).
