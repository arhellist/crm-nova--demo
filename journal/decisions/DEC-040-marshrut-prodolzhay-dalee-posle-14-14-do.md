# DEC-040 — После 14/14 done закрыть exit-criteria, R02 не стартовать без запроса

| Поле | Значение |
|------|----------|
| Дата | 2026-11-05 |
| Intake | 20261105-2352-ok-prodolzhay-dalee |
| Статус | принято |
| ADR | — |
| Заменяет | — |

**Контекст.** Запрос «Ок, продолжай далее» пришёл после зелёных гейтов и прогресса 14/14 done. `sp status` указывает следующий шаг `PIPELINE/R02_propose_change.md`, но R02 требует бизнес-запрос на изменение контракта и `kind: change` во входе. Intake-классификатор направил на `OUTPUT/prompts/Dxx_*.md`, хотя все D-срезы уже приняты. Одновременно `docs/exit-criteria.md` держит E1–E28 в статусе `pending` при наличии актов `evidence/D01.json`…`D14.json` — это незакрытый хвост сборки (шаг 10), а не новая разработка.

**Решение.** Маршрут «продолжай далее» после 14/14 done: закрыть exit-criteria E1–E28 доказательствами из evidence D01–D14 (статус `pass`, колонка «Доказательство» — существующие акты и связанные тесты/smoke), обновить мета-счётчики и прогнать `self-audit` / `pre_release` / `doctor --strict`. R02 / change-пакет не стартовать без явного бизнес-запроса на изменение. Intake `20261105-2352` перенаправляется с Dxx на `OUTPUT/docs/exit-criteria.md` + DEC-040.

**Альтернативы.** Стартовать R02 с выдуманным изменением — отвергнуто: изобретение объёма запрещено конституцией. Открыть новый D15 — отвергнуто: зелёное поле закрыто, новый срез без ТЗ расширяет поставку. Оставить E1–E28 `pending` — отвергнуто: критерии завершения продукта ложно показывают «открыто 28» при принятой поставке.

**Чем подтверждено.** `sp status`: 14/14 done, next = R02; `OUTPUT/docs/exit-criteria.md` до правки: Закрыто 0 / Открыто 28; акты `OUTPUT/evidence/D01.json`…`D14.json` с `tax_pass: true`; после закрытия — `sp verify --gate self-audit` и `doctor --strict`.
