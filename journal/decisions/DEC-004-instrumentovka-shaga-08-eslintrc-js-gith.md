**Контекст.** Репозиторий проекта — клон канона (`origin` = canon remote), а весь прогон живёт
незакоммиченным рабочим деревом: фабрика перенесена в `witness-done/`, артефакты шага 08 созданы, но
ничего не зафиксировано. Из-за этого `git status` показывает как «изменения» семь файлов
инструментовки шага 08, которых нет в `PRODUCES` ни одного задания: `.eslintrc.js`,
`.github/workflows/ci.yml`, `.gitignore`, `eslint-plugin-local-rules/{index.js,package.json}`,
`scripts/smoke/{product-smoke.sh,wave-api-smoke.sh}`. В нормальном проекте они коммитятся на шаге 08,
и проверка diff видит только код заданий. Здесь же `sp doctor --strict` падал с «изменены файлы вне
PRODUCES», то есть 10b не мог закрыться по причине, не относящейся к комплекту.

**Решение.** Инструментовка шага 08 вносится в baseline коммитом на отдельной ветке `nova-crm`
(`a2c68a1`); `main`, `origin` и копия фабрики в `witness-done/` не меняются, push не выполняется.
`main` остаётся историей канона на `25a7a13`, ветка `nova-crm` — рабочая история проекта.

**Альтернативы.** (1) Затереть `git`-историю или переинициализировать репозиторий — отвергнуто:
разрушительно и не нужно для проверки. (2) Добавить эти пути в `BOOKKEEPING_PREFIXES` канона —
отвергнуто: это правка фабрики, а `eslint-plugin-local-rules/` действительно код, а не бухгалтерия.
(3) Оставить `git status` как есть и записать «doctor неприменим» — отвергнуто: это повторяет
исходный дефект «зелёный отчёт при красном гейте».

**Чем подтверждено.** `sp doctor --strict` → `doctor: ok (strict)` после коммита `a2c68a1`;
`git log --oneline` показывает `a2c68a1` поверх канонного `25a7a13`; в коммите ровно семь путей
инструментовки, ни одного файла `witness-done/`.
