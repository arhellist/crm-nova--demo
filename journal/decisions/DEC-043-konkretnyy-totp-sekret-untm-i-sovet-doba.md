# DEC-043 — Секрет UNTM… не из ТЗ; MFA в ТЗ есть, хардкод — только локальный seed

**Контекст.** Пользователь справедливо указал, что фраза «TOTP-секрет UNTM… добавь в Authenticator» не выглядит как требование ТЗ, и спросил происхождение.

**Решение.** Конкретный TOTP-секрет `UNTMQM3SJ2OEHJJEMBXUH23VK44KBFWD` и совет «добавь в Authenticator» — не требование ТЗ, а артефакт локального seed (DEC-036) для воспроизводимого MFA на стенде и в e2e (`E2E_MANAGER_TOTP_SECRET`). В ТЗ есть только MFA/TOTP как продуктовое поведение (§2.1 п.1, §8, матрица MFA для `manager`); секрет при провижининге выдаётся пользователю (QR / enrollment), в production не хардкодится в git.

**Альтернативы.** Считать хардкод секрета требованием заказчика — отвергнуто: в ТЗ его нет. Убрать MFA из локального входа — отвергнуто: A04.1 / A14.1 / E11 проверяют второй фактор менеджера.

**Чем подтверждено.** `witness-done/INPUT/TECH_SPEC.md` §2.1 п.1, §8 (MFA TOTP); `supabase/seed.sql` + DEC-036; `e2e/global-setup.ts` / `runtime-plan.json` (`E2E_MANAGER_TOTP_SECRET`); отсутствие этой строки в §2.1–§12 как продуктового требования.
