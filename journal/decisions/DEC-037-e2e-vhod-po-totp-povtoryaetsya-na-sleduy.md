# DEC-037 — E2E-вход по TOTP повторяется на следующем 30-секундном окне, если первый код …

| Поле | Значение |
|------|----------|
| Дата | 2026-11-04 |
| Intake | — |
| Статус | принято |
| ADR | — |
| Заменяет | — |

**Контекст.** Supabase принимает каждый TOTP-код только один раз за 30-секундное окно, а приёмка логинит менеджера трижды: setup, desktop и mobile. Параллельные воркеры и код, вычисленный в конце окна, приводили к «Неверный код» и пустому `storageState`, хотя вход исправен.

**Решение.** E2E-вход по TOTP повторяется на следующем 30-секундном окне, если первый код отклонён. Причина: код, вычисленный в конце окна, приходит на сервер уже просроченным; параллельные desktop/mobile прогоны усиливали гонку. Это устраняет ложное «Неверный код» без ослабления MFA.

**Альтернативы.** Отключить MFA в e2e — отвергнуто: A14.1 01 проверяет второй фактор. Пропускать вход в mobile — запрещено (skip не считается приёмкой). Завести отдельные учётные записи на проект — отвергнуто: расширяет seed и матрицу ролей без продуктовой причины.

**Чем подтверждено.** `completeMfa` резервирует окно через файловый семафор и повторяет попытку на следующем окне; mobile-проект зависит от desktop; 34/34 e2e (desktop 1440 + mobile 360); runtime-гейт D14 `tax_pass: true`.
