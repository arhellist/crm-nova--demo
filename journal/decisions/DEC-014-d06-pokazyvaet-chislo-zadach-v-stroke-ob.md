# DEC-014 — D06 показывает число задач в строке объекта прочерком: контракт задач появляе…

| Поле | Значение |
|------|----------|
| Дата | 2026-11-04 |
| Intake | — |
| Статус | принято |
| ADR | — |
| Заменяет | — |

**Контекст.** HOW D06 п.3 требует в строке списка «название, адрес, число задач, дата», а
доменные правила запрещают показывать приблизительное число. Контракта чтения задач в D06 нет:
`src/features/tasks/**` создаётся в D07/D08, а считать задачи через `COUNT(*)` или самодельный
эндпоинт запрещено (`crud-table` конфликт offset/COUNT, INV-001 — запись только через Supabase).

**Решение.** D06 показывает число задач в строке объекта прочерком: контракт задач появляется только в D07, а выдумывать COUNT(*) или временный эндпоинт задач запрещено. После D07 колонка заполняется из данных задач по object_id, экран не меняет структуру.

**Альтернативы.** (1) Показать `0` — ложь: у объекта могут быть задачи, которые исполнитель
просто не видит. (2) Запросить `tasks?select=object_id` и посчитать на клиенте — это COUNT в обход
контракта и лишний трафик, плюс чтение задач вне RLS-проекции D07. (3) Скрыть колонку — расходится
с HOW и с макетом. Принято: прочерк без числа до D07, затем заполнение из данных задач.

**Чем подтверждено.** `src/features/objects/ObjectsPage.tsx` (ячейка «Задачи» с прочерком),
`A06.1`/`A06.5` в `src/features/objects/ObjectsPage.test.tsx`; `sp verify --d D06 --gate pre_ci`
= `tax_pass: true`.
